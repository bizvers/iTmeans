# शब्द का डेटा-रिकॉर्ड

हर शब्द एक JSON फ़ाइल: `content/words/<domain>/<subtopic>/<slug>.json`। वेबसाइट इन्हीं ख़ानों से इन्फोग्राफ़िक बनाती है। नमूना: `content/words/web-development/backend/cache.json`।

| ख़ाना | क्या रखता है | नियम |
| --- | --- | --- |
| `id` | पक्की पहचान, जैसे `w-k3m9x2qa` | अनिवार्य; **कभी नहीं बदलती** (नाम, slug या उप-विषय बदलें तब भी); सिर्फ़ कोड बनाता है (AI/CMS नहीं); पूरे कोश में अनोखी |
| `term` | अंग्रेज़ी शब्द | अनिवार्य; पहला अक्षर `letter` से मिले |
| `domain`, `subtopic` | क्षेत्र और उप-विषय की id | `content/taxonomy/taxonomy.json` में से ही |
| `letter` | A–Z | कोड निकाले, AI नहीं |
| `slug` | पन्ने का पता, जैसे `cache` | सिर्फ़ पते के लिए; उप-विषय में अनोखा; पहचान `id` से चलती है |
| `level` | `basic` / `advanced` | अनिवार्य |
| `pronunciation_hi` | देवनागरी उच्चारण | अनिवार्य |
| `term_hi` | प्रचलित हिंदी शब्द | वैकल्पिक; गढ़ा हुआ अनुवाद नहीं |
| `literal_meaning` | शाब्दिक अर्थ | `{hi, en}`; एक वाक्य |
| `field_meaning` | इस क्षेत्र में अर्थ | `{hi, en}`; अधिकतम दो वाक्य |
| `effect` | असर | `{hi, en}`; कोई अंक/प्रतिशत नहीं |
| `effect_flow` | "एक नज़र में असर" के 3 कदम | 3 छोटे कदम, `{hi, en}` हर कदम |
| `usage` | प्रयोग: कहाँ और कब | `{hi, en}` |
| `example` | एक उदाहरण | `{hi, en}` |
| `caution` | सावधानी / आम ग़लती | `{hi, en}` |
| `related` | जुड़े शब्द | 2–5 **id**; हर id कहीं मौजूद हो (छपा शब्द, कतार का शब्द या रोका हुआ); वरना build रुकता है। AI शब्द के नाम लौटाता है, कोड उन्हें id बनाता है और नए शब्द कतार में रखता है |
| `status` | `published` / `held` | कोड तय करे |
| `written_by`, `checked_by` | मॉडलों के नाम | लिखने वाला और दोनों जाँचने वाले अलग कंपनियों के |
| `created_at`, `checked_at` | ISO तारीख़ें | कोड भरे |
| `hold_reason` | रुकने का कारण | सिर्फ़ `held` पर |

लंबाई की सीमाएँ (ताकि घने रूप की एक पंक्ति में बैठे): `field_meaning.hi` का पहला वाक्य ≤ 60 अक्षर; यही सूची की एक-पंक्ति वाला अर्थ बनता है।

## भाषाएँ कहाँ रहती हैं (तीन अलग चीज़ें)
| क्या | कहाँ | नियम |
| --- | --- | --- |
| शब्द की पहचान | शब्द-फ़ाइल: `id`, `term`, `slug`, `domain`, `subtopic`… | भाषा से मुक्त |
| हिंदी + अंग्रेज़ी पाठ | उसी शब्द-फ़ाइल में `{hi, en}` | चक्र की जाँच इन्हीं दो को माँगती है |
| बाक़ी भाषाओं का पाठ | `content/translations/<भाषा>/<शब्द की id>.json` | सादे पाठ: `literal_meaning`, `field_meaning`, `effect`, `usage`, `example`, `caution` और `effect_flow` (ठीक 3); न मिले तो अंग्रेज़ी दिखे |
| साइट के बटन/लेबल | `content/ui/<भाषा>.json` | हर चालू भाषा में `en.json` की सारी कुंजियाँ |
| भाषाओं की सूची | `content/taxonomy/taxonomy.json` | एक ही जगह; `active` से चालू |

नई भाषा चालू करना: `content/ui/<कोड>.json` जोड़ें → taxonomy में `active: true` → (अनुवाद धीरे-धीरे `translations/` में)। जाँच बिना UI-फ़ाइल या अधूरी UI-फ़ाइल पर build रोकती है; अनुवाद बाक़ी हों तो सिर्फ़ चेतावनी। (नई भाषा के अनुवाद लिखने वाला चक्र और 20 नमूना शब्दों की जाँच अलग क़दम में आएँगे।)

## दूसरी फ़ाइलें
- `content/taxonomy/taxonomy.json` — क्षेत्र, उप-विषय, हिंदी नाम, रंग-क्रम।
- `content/queue/<domain>__<subtopic>.json` — लिखे जाने वाले शब्द: `{id, term, both}` (दो मॉडल जो शब्द बताएँ वे आगे)। कतार में आते ही शब्द को id मिलती है और छपने पर वही रहती है। छपने या रुकने पर प्रविष्टि कतार से हटती है।
- `content/held/` — रोक-सूची: वही `id` + `hold_reason` + जाँचने वालों की आपत्तियाँ।
- id बनाने/भरने के औज़ार: `npm run assign-ids` (site/ में) किसी भी बिना-id रिकॉर्ड को id देता है; `scripts/migrate-ids.mjs` एक बार का पुराना-से-नया बदलाव था।
- `content/ledger/<YYYY-MM-DD>.jsonl` — हर घंटे की एक पंक्ति: छपे, रुके, किस सेवा की सीमा कितनी बची, गड़बड़ियाँ। चाबी का कोई हिस्सा कभी नहीं।
